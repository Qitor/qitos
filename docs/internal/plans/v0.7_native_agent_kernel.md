# v0.7 Native Agent Kernel Design

Status: design (no implementation yet)
Execution decomposition: `docs/v4/01-baseline-absorption.md` (mechanism landing), `docs/v4/02-conversation-kernel.md` (Pillars A+B), `docs/v4/03-aci-toolset.md` (Pillar C, grounded in the Cyborg tool-layer reference at `~/Downloads/Cyborg/cybergym_agent/`), `docs/v4/04-context-injection-and-memory.md` (Pillars D+F), `docs/v4/05-trajectory-data-plane.md` (Pillar E + observability generalization).
Parent: `cybergym_campaign_absorption.md` (v2). This document turns the campaign's six most-felt lessons into first-class framework design. Every item below passes the domain-neutrality test (absorption plan §1).

The six lessons, as reported from the campaign:

1. Native support for **parallel tool calls** (one assistant turn, N tool calls, N results).
2. **Message-stack orchestration** matching the modern model-calling paradigm: `system, user, assistant#A (tool_calls+results) => assistant#B (…) => …`, with optional user **steering** turns, and **reasoning preservation** (GLM-style preserved thinking).
3. A complete, well-designed **native ACI toolset**.
4. Claude-Code-style **runtime context injection** (our `RUNTIME_CONTEXT`, generalized).
5. **Space-efficient trajectory storage** aligned with mainstream agent trajectory formats.
6. Curated, proven **generic kit modules** (memory et al.).

Design goal, verbatim from the framework's position: make it trivially easy for a researcher to build a production-shaped agent. DX is an acceptance criterion, not an afterthought.

---

## 0. Design principles

1. **The message stack is the kernel object.** Models are trained on this shape; the framework's job is to keep it canonical internally and compile it faithfully per provider. Agents should never hand-assemble provider JSON.
2. **Mechanism only** (neutrality test applies to every symbol added here).
3. **Defaults from FamilyPresets.** A user who picks a preset gets the correct protocol, reasoning policy, delivery policy, and request kwargs without reading provider docs.
4. **Everything observable.** Every policy decision (delivery mode used, reasoning dropped/preserved, injection revision) appears in trace events.
5. **Campaign-hardened invariants become validators**, not folklore: no orphan tool results, exactly-one decision context, no unintended trailing user turn, state-never-lost fallback.

## 1. Pillar A — Conversation orchestration (`qitos.core.conversation` + compiler in models/harness)

### Canonical turn model

```python
SystemTurn(content, anchor=...)                    # anchor marks cache-stable prefix
UserTurn(content, kind="task" | "steering", source="human" | "runtime")
AssistantTurn(content, tool_calls=[ToolCall(id, name, arguments)],
              reasoning=ReasoningPayload(...))      # reasoning preserved canonically
ToolResultTurn(tool_call_id, name, content, is_error=False, summary=None)
```

`Conversation` is an append-only, invariant-validating stack:
- tool results must reference an open tool_call of the immediately preceding assistant turn;
- an assistant turn with tool_calls cannot be closed until all its results arrive (interrupted-call recovery excepted);
- steering turns carry `source` so audit distinguishes human steering from runtime injection.

### Policies (per FamilyPreset, overridable)

| Policy | Options | Default rationale |
|---|---|---|
| `ReasoningPolicy` | `drop` · `preserve_inline` · `signed_blocks` · `item_reference` | GLM: preserve_inline (official preserved-thinking guidance — improves continuity and cache hits; `clear_thinking=false` semantics). Anthropic: signed_blocks (thinking blocks must round-trip with signatures). OpenAI Responses: item_reference (reasoning items passed back). DeepSeek-R: drop. |
| `ContextDeliveryPolicy` | `user_turn` · `merge_tool` | campaign-proven: `merge_tool` appends runtime context into the trailing tool result so the conversation ends on tool results (GLM chat-template safe); `user_turn` is the universal fallback. Invariant: on merge failure, fall back to `user_turn` — state is never lost. |
| `SteeringPolicy` | placement rules for mid-run user turns | steering allowed only at turn boundaries (after a completed results batch), marked in trace. |

### Compilers

`compile_chat_completions(conv, policies)`, `compile_responses_items(...)`, `compile_anthropic(...)` — the only place provider JSON is built. They honor reasoning policy, delivery policy, cache anchors (stable system prefix for prompt-cache hits), and emit telemetry (what was dropped/preserved/merged).

### Engine integration

`_model_runtime` delegates message assembly to `Conversation`; the existing stream-transformer seam remains the pre-send hook for advanced users. Campaign commits absorbed here: RUNTIME_CONTEXT wrapper, merge_tool (72d3d7d), decision-context packet normalization (05a1c82), orphan-tool-result eviction (mainline), reasoning field preservation (75e3c53/5452e23/71bb4e1).

## 2. Pillar B — Native parallel tool calls

- `Decision` carries `actions: list[Action]` (1..N); protocol capability `supports_multi_action` (`json_decision_multi_v1` contract already exists — keep, with its combination rules: only side-effect-free grouping, no read-after-write in one batch, bounded N).
- Provider negotiation via preset `recommended_request_kwargs` (`parallel_tool_calls=True` where supported; Anthropic parallel `tool_use` blocks are native).
- Execution (campaign fixes, WS1/WS3): four-level concurrency adjudication (policy whitelist → approval veto → explicit `concurrency_safe` → read-only heuristic); partial blocking allowed — blocked siblings get error cards, unblocked siblings still execute; results merged in original order; deterministic `tool_call_id` correlation; loop detector records only executed actions (opt-out knob retained).
- History shape: exactly one assistant turn with N tool_calls followed by N tool results — Pillar A guarantees the shape models expect.
- Render/trace: multi-action banners and per-index observations (campaign work lands unchanged).

## 3. Pillar C — Native ACI toolset (`qitos.kit.aci`)

Claude-Code-proven, domain-neutral inventory: `read`, `grep`, `glob`, `bash`, `edit`, `write`, `todo` (task board), `fetch` (HTTP, opt-in), `spawn_agent` (opt-in handoff wrapper). Domain-flavored campaign tools (HexView, StructProbe, CallsiteSearch, …) stay in cybergym-agent.

Per-tool design rules (the ACI quality bar):

1. **Token-efficient output**: line-numbered reads, `grep` with `output_mode`/`head_limit`/`offset`, hard size caps with continuation affordances ("pass `offset=N` to see more") — outputs teach the model how to paginate itself.
2. **Stable, authored schemas**: fixed names/descriptions/params; authored description wins over docstring (WS2 contract); schema stability = prompt-cache hits.
3. **Declared metadata**: `read_only`, `concurrency_safe`, `needs_approval`, `output_budget` — feeds Pillar B adjudication directly.
4. **`model_summary` projection** for large structured outputs (canonical data kept in trace, summary goes to the model).
5. **Permission-gated**: workspace sandbox for fs tools, bash allowlist; the campaign's symlink loosening becomes an explicit `allow_symlink_escape` flag here, deny-by-default.
6. **Failure cards**: errors return actionable text cards (unknown tool names list available tools — campaign behavior), never opaque wrapped JSON.

DX target: `from qitos.kit.aci import coding_toolset; tools = coding_toolset(bash=True, net=False)`.

## 4. Pillar D — Runtime context injection (mechanism-only `RUNTIME_CONTEXT`)

Engine-level injector registry, the neutral generalization of Claude Code's `<system-reminder>` and our campaign block:

```python
class ContextInjector(Protocol):
    name: str
    revision(state) -> int            # unchanged content => no re-injection (token savings)
    render(state) -> str              # neutral wrapper tag, e.g. <SYSTEM_CONTEXT source="qitos-runtime">
    budget_chars: int
```

- Engine applies injectors per `ContextDeliveryPolicy`; every application is a trace event with name + revision + chars; TUI display is opt-in (blocks are large).
- A model-facing protocol note ships as a kit prompt resource ("this block is authoritative controller state, not tool output; act on it, do not quote it back").
- Budget caps per injector; overflow truncates with a pointer to the artifact store (Pillar F memory).

## 5. Pillar E — Trajectory data plane

Base: the campaign's canonical store (4b8c8a0), extended:

- **Store**: append-only per-run manifest (JSONL) + content-addressed blob store (sha256) with zstd compression; messages and tool schemas deduplicated by hash (store once, reference everywhere). Optional SQLite index for query-heavy analysis.
- **Exporters** (the ecosystem's convergence points): `openai_record` (native messages + tools schema), `sharegpt_record` (Hermes/Axolotl-compatible training JSONL), `swift_record` (ms-swift, loss-masked). Later: Letta-style agent-experience records, OpenTelemetry GenAI spans.
- **Redaction** built into every export path (`safe_projection`: keys, bearers, hosts, tokens).
- **qita** reads the canonical store directly; replay is a deterministic rebuild from the manifest.
- Acceptance: round-trip tests per exporter; a campaign run converts to both OpenAI and ShareGPT formats; measured size ≥10× smaller than naive per-step JSON dumps (dedup + zstd).

## 6. Pillar F — Curated kit surface (proven generic modules)

- **memory**: MemDir upgrade with evidence-pointer index (`INDEX.md`), durable declared fields surviving compaction, externalized large payloads with lightweight pointers (WS4 mechanism — the campaign's evidence memory, neutralized).
- **history**: protected head/tail slide-window as a first-class `HistoryPolicy` with whole-step trimming and provider-neutral budget knobs (WS4).
- **planning / critics / permission / skill**: existing kit modules stay the extension points; no new strategy components enter (absorption plan §6 audit governs).

## 7. Developer-experience acceptance criteria

1. A ~50-line, runnable coding agent (system prompt + `coding_toolset()` + preset model + engine) that uses parallel tool calls, preserved reasoning, and runtime context — shipped as an executable example and CI-tested tutorial.
2. Choosing a preset yields correct protocol/reasoning/delivery defaults with zero provider-doc reading; every default is overridable in one constructor argument.
3. One flag turns on trajectory export in ShareGPT or OpenAI format.
4. Migration from the current `AgentModule` API is additive; any breaking change ships with release notes (absorption plan §10).
